Admin: Allowed websites

Workspace settings > Security > Allowed websites (org admins). Same section as the API: PUT /api/v1/control-plane/policy/org/current/websites

Agents run code in a sandbox that cannot reach the internet. Turn on the sites they may use. Every request is checked, counted against the run's outside-traffic limit and shown in the run's activity. Off by default.

Keep every site read-only unless an agent must send data there. Read-only allows reading pages and downloading packages, never uploading.

Choosing "Read and write"

Let agents send data to mirror.acme.net?

With read and write, an agent can upload files and send any data this run has seen to mirror.acme.net. If a conversation has read private data, PipesHub asks the person before each run uses it.

Host-level only (advanced)

Host-level only: the agent can send data to this host, and PipesHub cannot see or limit what it sends.

Use only for a program that refuses PipesHub's inspection (a pinned client or an internal mirror). Not offered for package registries, git hosts or paste and storage sites. Needs the deployment's tunnel switch.

Offer host-level only behind an "Advanced" disclosure and only when the deployment's tunnel switch is on.

Admin: Git hosts for cloning

Workspace settings > Security > Git hosts for cloning (org admins)

Agents never reach git hosts from their sandbox. When an agent needs a repository, PipesHub clones it outside the sandbox after the person approves, and hands the agent a copy. Pushing is never possible this way.
